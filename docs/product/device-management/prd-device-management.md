Companion files: the journeys are in [prd-device-management-journeys.md](prd-device-management-journeys.md), the shipping copy in [prd-device-management-copy.md](prd-device-management-copy.md), the answers to part-closed open questions in [prd-device-management-oq-results.md](prd-device-management-oq-results.md), and the owner's decisions in [prd-device-management-fences.md](prd-device-management-fences.md); `prd-device-management-dogfood-results.md` lands beside this PRD only once observations exist (M6/M7).

## Build contract

Owns discovery, connection identity, saved devices, offline license activation, device authorization, calibration, readiness, halt/recovery, and the mock contract for v1 Spectro 2/L. Serves [vision U3, U8 and U9](../vision.md#use-cases).

Requirement rows own behavior; [acceptance scenarios](prd-device-management-journeys.md) derive assertions from them; [copy](prd-device-management-copy.md) owns displayed text. Stable row IDs, priorities, statuses and historical fences remain traceable; this amendment is a specification change, not an implementation completion.

Capture owns queue navigation, per-scan retry/skip/flag, session endings and interruption recovery; Data Foundation owns durable measurements and their device snapshots; Collection Mode owns collection presentation. See [Inherited obligations](#inherited-obligations) for exact source rows; architecture remains in [ADRs](../../decisions/README.md).

### Traceability

Three row-ID families, one per dispositionable table, all under one rule: an ID is assigned once and never renumbered — a row that is cut or deferred keeps its ID rather than freeing it for reuse. Fence F9 assigned every ID in this document and its companions; before that pass the rows carried none, so no ID here supersedes an earlier one.

- Every requirement row in [§1](#1-device-pairing) through [§6](#6-mock-device-layer) carries an ID of the form `R<section>.<n>` — for example `R5.7`.
- Every state row in the [copy file](prd-device-management-copy.md#error--state-copy) carries an ID of the form `E<n>`.
- Every metric row in [Success Metrics](#success-metrics) carries an ID of the form `M<n>`.

The Commit PR column is where a row maps onto the work that lands it. Owner decisions F1–F30 are recorded in the [fence file](prd-device-management-fences.md); where a row names one it is for provenance only, and no row re-argues one. Which rows carry each fence is that file's "Fence → row map".

### 2. Licensing & Pre-Authorization

Traces [UJ1](prd-device-management-journeys.md#uj-1-first-run), [UJ1.1](prd-device-management-journeys.md#uj-11-cannot-complete-a-first-run), [UJ6](prd-device-management-journeys.md#uj-6-pre-authorize-before-going-offline), [UJ6.1](prd-device-management-journeys.md#uj-61-authorization-window-expired-while-offline); serves [U8](../vision.md#use-cases).

Vocabulary: "pre-authorization" is internal vocabulary and never appears in the UI — the button is "Extend offline use" and the panel string is "Offline use through ⟨date⟩".

Two authorization layers, named ([SDK audit](../../briefs/nix-universal-sdk-audit-findings.md), per SDK docs; confirm on hardware — OQ 1, OQ 8): app-level license activation is offline, client-side signed, and happens on every launch — it needs no internet; device-level serial authorization is online for an unknown device, then cached ~30 days. "No internet" failures belong to the device layer, never to activation. The SDK's private-label exemption from online device checks exists ([SDK audit](../../briefs/nix-universal-sdk-audit-findings.md), per SDK docs) and is out of scope for v1 — recorded here so it isn't rediscovered.

### 7. Error & State Copy

The shipping copy for every error, waiting, and blocked state in this PRD is in [prd-device-management-copy.md](prd-device-management-copy.md). Confirmation dialogs and warn-level presentations reuse the copy of the rows that require them ([R4.3](#4-pre-flight-device-health)). Copy is written in the Cataloger's vocabulary: plain language, names the recovery, never SDK-speak.

Every state there is a distinct, named state whose identity is stable even when its copy changes, so behavior can be asserted independently of wording; that table is a P0 requirement and every state row carries its own status, a value from the [Legend](#legend). The journeys and the requirement rows link to a state rather than restating its copy. A state whose name is marked ‹P1› does not appear until its own rows land, and a marked action inside an unmarked state is withheld until then — the P1-seam convention ([R4.4](#4-pre-flight-device-health)).

**Placeholders.** ⟨…⟩ stands for something filled in when the state is shown. The tokens in use: ⟨model⟩ the device's model name, ⟨serial⟩ its serial, ⟨name⟩ the discovery entry's device name, ⟨date⟩ an offline-use end date, and ⟨code⟩ the held reading's swatch code in E33. Where the serial is not yet readable, a state naming "⟨model⟩ (⟨serial⟩)" shows [R1.7](#1-device-pairing)'s provisional display form — the discovery entry's name and transport, "⟨name⟩ — Bluetooth" — instead.
