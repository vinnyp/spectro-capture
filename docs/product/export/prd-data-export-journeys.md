# Data Export PRD — acceptance scenarios

Companion to [prd-data-export.md](prd-data-export.md). The [EJ1 index](prd-data-export.md#user-journeys) owns row coverage; these scenarios assert the contract without adding rules. Copy identities are [E1–E4](prd-data-export-copy.md#error--state-copy); marked ‹P1› cases run only once R1.3 lands. [DF R7.7a–m](../data-foundation/prd-data-foundation.md#fixture-matrix) is the sole fixture inventory; scenarios compose those fixtures and declared states rather than defining another inventory.

## EJ1. Export the collection

| Case / setup | Action | Expected result |
| :--- | :--- | :--- |
| Collection with queue order different from insertion order | Canonical export, then repeat with identical inputs/build | One row per item in queue order, chosen condition named, identical complete bytes; source values/marks/notes unchanged at SQLITE_READER_FLOOR (R1.1a–g, R2.3, R4.1b/R4.3) |
| Single item from that collection | Open E1 and export | Same surface, counts scoped to this item; one canonical row, or ‹P1› its complete history; other items do not contribute disclosures or rows (R1.1a/o–q) |
| Imported passthrough values such as `0007`, `1,234.5`, quoted commas/newlines; identity-mapped column | Import → store → export; parse emitted CSV | Decoded values unchanged; mapped identity emitted once; quoting/dialect per R2.2, missing per-item values empty; no vendor credential in either kind (R2.3/R2.4, R4.2, DF R7.7b) |
| Stored columns from two imports, including literal `import_` names | Export each R2.4 example and repeat after an import with reordered headers | Allocate in persisted collection-column order; earlier columns win; repeat prefixes until unique; preview every original → emitted pair; source column names/values unchanged (R2.4a–c, DF R7.7a/k) |
| Never-scanned item and item whose current reading is quarantined | Canonical export | Identity/import/version/kind/condition/state present; remaining reading fields empty, including snapshot/`sc_simulated`; no promotion of readable history; canonical states differ by cause (R1.1h) |
| Healthy current with quarantined history, then quarantined current with readable history ‹P1› | History export | Quarantined wins over superseded; damaged row’s colour/spectral/payload/qualifier fields empty, readable provenance retained; healthy current alone is flagged true in first case, every flag false in second (R1.1f/i) |
| Non-spectral, missing-condition and gamut-clipped readings | Export each | Original-reference six spaces for non-spectral readings when condition exists; absent chosen-condition values empty, no substituted condition; emitted sRGB/HSL carry reference/intent/gamut qualifiers; `sc_simulated` matches known live/simulated snapshots (R1.1j/k, R1.2, R2.1; DF R7.7c–f) |
| Archive-only damage mixed with unused sample slots | Export and inspect E1 | Intact reading values remain, unavailable/unused payload cells empty; no new archive state/column; preview counts unavailable archives only, and promises only available payloads (R1.1d/l/p) |
| A → B → C, correction/re-measurement answers and restored reading ‹P1› | History export | One row per item reading, sequence ascending; incoming reason belongs to that row, not its predecessor; restore keeps original measurement time with new sequence; only canonical flagged current; no QC record or superseded derived set becomes an extra version (R1.1e–g, DF R7.7g) |
| Never-scanned item mixed with history ‹P1› | History export | One identity row for unscanned item, empty ordinal/reason, false current flag; row count includes it once (R1.1h/o) |
| Empty collection | Open E1 and export each available kind | Explicit column-names-only copy, no absent-data claims/zero counts; kind/version disclosure and applicable actions remain; correct header, zero data rows (R1.1r, R4.1h) |
| Interpretable healthy file declared read-only | Export to writable destination | Success; source read-back identical (R1.1m, R4.3) |
| Each uninterpretable/file-level-invalid state | Inspect offered actions | Export absent; DF owns recovery; read-only alone is not the refusal criterion (R1.1n, R4.3) |
| No room, no permission, destination gone; each also induced mid-write | Attempt export | Corresponding E2/E3/E4, Retry and alternate-destination actions; no partial output, missing file or source change (R3.1/R4.3) |
| P0 versus P1 build | List E1–E4 actions and disclosures | History controls/sentences withheld until R1.3 lands; kind-specific counts, condition, available content, rename pairs and recovery actions match R4.4a, not exact copy strings |

Golden maintenance follows [R4.1a–h](prd-data-export.md#golden-acceptance): app-version exception only for golden comparison, full-byte repeat comparison, reviewed append/derivation diffs, new goldens for breaking format changes, header-only scale assertion, and provisional wavelength exclusion until OQ 4 closes. No scenario claims hardware validation or a completed implementation.
