# Data Export PRD — acceptance scenarios

Companion to [prd-data-export.md](prd-data-export.md). The [EJ1 index](prd-data-export.md#user-journeys) owns row coverage; these scenarios assert the contract without adding rules. Copy identities are [E1–E4](prd-data-export-copy.md#error--state-copy); marked ‹P1› cases run only once R1.3 lands. [DF R7.7a–n](../data-foundation/prd-data-foundation.md#fixture-matrix) is the sole fixture inventory; scenarios compose those fixtures and declared states rather than defining another inventory.

## EJ1. Export the collection

| Case / setup | Action | Expected result |
| :--- | :--- | :--- |
| Collection with queue order different from insertion order | Canonical export, then repeat with identical inputs/build | One row per item in queue order, chosen condition named, identical complete bytes; source values/marks/notes unchanged at SQLITE_READER_FLOOR (R1.1a–g, R2.3, R4.1b/R4.3) |
| Single item from that collection | Open E1 and export | Same surface, counts scoped to this item; one canonical row, or ‹P1› its complete history; other items do not contribute disclosures or rows (R1.1a/o–q) |
| Imported passthrough values such as `0007`, `1,234.5`, quoted commas/newlines; identity-mapped column | Import → store → export; parse emitted CSV | Decoded values unchanged; mapped identity emitted once; quoting/dialect per R2.2, missing per-item values empty; no vendor credential in either kind (R2.3/R2.4, R4.2, DF R7.7b) |
| Stored columns from two imports, including literal `import_` names | Export each R2.4 example and repeat after an import with reordered headers | Allocate in persisted collection-column order; earlier columns win; repeat prefixes until unique; preview every original → emitted pair; source column names/values unchanged (R2.4a–c, DF R7.7a/k) |
| Never-scanned item and item whose current reading is quarantined | Canonical export | Never-scanned has empty reading fields; quarantined current retains readable snapshot/`sc_simulated`, basis and measured-at, with colour/spectral/qualifier cells empty and payloads per R1.1d/l; no history promotion (R1.1h/s) |
| Healthy current with quarantined history, then quarantined current with readable history ‹P1› | History export | Quarantined wins over superseded; damaged row’s colour/spectral/qualifier fields empty, payload cells follow R1.1d/l and readable provenance remains; healthy current alone is flagged true in first case, every flag false in second (R1.1f/i) |
| Non-spectral, missing-condition and gamut-clipped readings | Export each | Original-reference six spaces for non-spectral readings when condition exists; absent chosen-condition values empty, no substituted condition; emitted sRGB/HSL carry reference/intent/gamut qualifiers; `sc_simulated` matches known live/simulated snapshots; empty is unknown, not false; original-reference mismatch is derivable with no separate export mark and disclosed in E1 (R1.1j/k, R1.2, R2.1; DF R7.7c–f) |
| Archive-only damage mixed with unused slots and a sample whose instrument supplied no payload (DF R7.7i) | Export and inspect E1 | Intact reading values remain, unavailable/unused/never-supplied payload cells empty; no new archive state/column; preview counts unavailable archives only, and promises only available payloads (R1.1d/l/p) |
| A → B → C, correction/re-measurement answers and restored reading ‹P1› | History export | One row per item reading, sequence ascending; incoming reason belongs to that row, not its predecessor; restore keeps original measurement time with new sequence; only canonical flagged current; reason tokens use DF’s exact hyphenated spelling, record time absent; no QC record or superseded derived set becomes an extra version (R1.1e–g, DF R7.7g) |
| Never-scanned item mixed with history ‹P1› | History export | One identity row for unscanned item, empty ordinal/reason, false current flag; row count includes it once (R1.1h/o) |
| Newly created empty collection with no imported columns (DF R7.7n) | Open E1 and export the selected kind | Explicit column-names-only copy, no absent-data claims/zero counts; kind/version disclosure and applicable actions remain; correct header, zero data rows (R1.1r, R4.1h) |
| Interpretable healthy file declared read-only | Export to writable destination | Success; source read-back identical (R1.1m, R4.3) |
| Newer/below-floor and each file-level-invalid state | Inspect offered actions | Export absent; DF owns recovery; read-only alone is not the refusal criterion (R1.1n, R4.3); R4.2 excludes refused states from golden comparisons |
| No room, no permission, destination gone; each also induced mid-write | Attempt export | Corresponding E2/E3/E4, Retry and alternate-destination actions; no partial output, missing file or source change (R3.1/R4.3) |
| P0 versus P1 build | List E1–E4 actions and disclosures | History controls/sentences withheld until R1.3 lands; kind-specific counts (row count only if different), condition, export/app versions, available content, rename pairs, E1a–g variants and recovery actions match R4.4a, not exact copy strings |
| Case/whitespace header variants (DF R7.7a) | Export `SC_Simulated` and ` sc_simulated ` in separate fixtures, with literal `import_` collisions | Both tests use Import R2.3; preserve original spelling/spacing in emitted prefixed names; no equivalent duplicate headers (R2.4b) |
| App-column append versus value-form change | Append an app column, then separately change numeric precision or boolean spelling | Append retains format version and refreshes golden in place before passthrough; form change increments version and creates new golden, retaining old golden; other R2.5 breaking changes (remove/rename/reorder/meaning/grid) also bump; help docs contain every R2.5 statement (R4.1a/c/e, F12) |

Payload assertions compare the decoded CSV cell with the instrument-supplied string byte-for-byte, whether its stored archive was compressed or not (R1.1d/R4.1a, F30).

Golden maintenance follows [R4.1a–h](prd-data-export.md#golden-acceptance): literal `__APP_VERSION__` in golden data cells, actual version validated before substitution only for golden comparison, full-byte repeat comparison, reviewed append/derivation diffs, new goldens for breaking format changes, header-only scale assertion, and provisional wavelength exclusion until OQ 4 closes. No scenario claims hardware validation or a completed implementation.
