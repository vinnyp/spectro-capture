# Inventory Import PRD — error & state copy

Companion to [prd-inventory-import.md](prd-inventory-import.md): the shipping copy for every state that PRD names.
State IDs are local and stable; E4–E14, E38 and E40 retain their inherited numbers, and E41–E45 are new in this amendment; E46–E49 are new in the Nix Toolkit export amendment (F69–F91). [Capture §12](../capture-mode/prd-capture-mode.md#12-error--state-copy) owns labels/placeholders; [the Legend](prd-inventory-import.md#legend) owns statuses; [R3.8](prd-inventory-import.md#3-preview-and-commit) owns action transitions.

Copy uses the Cataloger’s vocabulary, never SDK-speak. Every promise below is backed by a requirement row in the PRD.

Variants share a state ID; tests can distinguish the cause without matching text. Variant and scope labels below are documentation, not displayed text; render only the applicable body and actions. All offered actions below are observable under R4.1. Every listed state offers Cancel, including E44 after a failed commit; an in-progress commit finishes or rolls back under R3.2.

E43 renders the target and nonzero existing count as first-class lines, with encoding/delimiter controls always visible (R3.8n), except for a Toolkit export, whose settings are shown fixed without controls (R6.1). Lists show names and source record numbers, omitting empty list lines and zero-count sentences under Capture §12; keep the target’s name visible independently of the existing-item count. `⟨n⟩` in its warning is resulting collection size; `⟨ceiling⟩` is ROWS_CEILING. Other count placeholders name the corresponding R3.6 count, with `⟨filled⟩` counting matched rows that gain absent fields under R3.6j; `⟨encoding⟩` and `⟨delimiter⟩` name the current read settings. The Toolkit tokens are R6.4's and R6.9's: `⟨readings⟩` the eligible records' readings; `⟨current⟩`, `⟨history⟩` and `⟨same⟩` its three reading counts, which sum to `⟨readings⟩`; `⟨mode⟩` the file's measurement mode, `⟨setting⟩` the target's before the import, `⟨modes⟩` the modes a mixed file holds; `⟨resolved⟩` the set-aside items it captures; `⟨differing⟩` and `⟨unchecked⟩` R6.6's lists; `⟨clashes⟩` R6.8d's same-dated records; `⟨collections⟩` the Toolkit collection names a file holds; `⟨record⟩` the one-based record number E5's Toolkit quotes variant names (R1.4). The mode-change sentence shows only where R6.4 adopts a mode.

E5, E7, E9, E10 and E42 carry Toolkit variants, written out in their rows, because editing a Toolkit export in a spreadsheet can change its form (R6.1). When a Toolkit export creates its target, Capture §1's creation form shows the scan mode as "Measurement condition: ⟨mode⟩, set by this Nix Toolkit export" (R6.3).

E44’s no-room variant carries [Data Foundation E15](../data-foundation/prd-data-foundation-copy.md#error--state-copy)’s cause and remedy; import retry always returns through a fresh preview (R3.8l). File movement uses the existing file-management surface after Cancel; the whole-or-nothing durability guarantee has [DF R1.7/R1.10](../data-foundation/prd-data-foundation.md#1-the-file-the-user-owns)’s local-volume scope.

## Generated column names

E12/E41 list each affected source position, original header (display “Unnamed” for blank), and final name. R2.5 owns collision order and R2.3 owns comparison; the naming strings are:

| Use | Template | Substitution |
| :--- | :--- | :--- |
| Blank header | `Column ⟨position⟩` | One-based source column position (for example, `Column 2`). |
| Collision | `⟨base⟩ (⟨suffix⟩)` | Original named header or generated blank name; suffix starts at 2 and increments until unique (for example, `Notes (2)`). |

The templates are part of saved header identity and must remain stable across reads. E12 and E41 may appear together; “Continue with the listed names” accepts all displayed resolutions (R3.8o).
