# Data Foundation PRD — error & state copy

Companion to [prd-data-foundation.md](prd-data-foundation.md): the shipping copy for every state that PRD names.
Each `E<n>` ID is the contract between a state and the rows that cite it; IDs never renumber. The Status column holds a value from that PRD's [Legend](prd-data-foundation.md#legend). A state whose name is marked ‹P1› does not appear until its own rows land, and a marked action inside an unmarked state is withheld until then — the P1-seam convention the sibling PRDs use. The collection-unavailable state is the [capture PRD's E26](../capture-mode/prd-capture-mode-copy.md#error--state-copy)'s and the halt and pre-flight states are the [device PRD's](../device-management/prd-device-management-copy.md#error--state-copy); neither is restated here.

**Placeholders.** ⟨…⟩ stands for something filled in when the state is shown: ⟨code⟩ a Swatch Code, ⟨collection⟩ a collection's name, ⟨n⟩ a count of items or readings, ⟨size⟩ a file size, ⟨path⟩ a file location, ⟨version⟩ an app or file version, ⟨date⟩ a date. A sentence whose count would be zero is left out rather than shown as "0"; a sentence carrying a count agrees with it — "1 reading", "⟨n⟩ readings"; and a named provisional constant renders as the number it currently holds, never as its name.

## Error & state copy

Written in the Cataloger's and the Data consumer's vocabulary: plain language, names the recovery, never SDK-speak, never a schema word. Every promise below is backed by a requirement row in the PRD ([process rule 5](prd-data-foundation.md#legend)).

| ID | State | Headline | Body | Primary action | Status |
| :--- | :--- | :--- | :--- | :--- | :--- |
| E1 | File from a newer app | This file was made by a newer version of SpectroCapture | You can look at it, but you can't change it until you update. Your file hasn't been touched. It was written by version ⟨version⟩ and this is version ⟨version⟩. | Update SpectroCapture; Open it read-only | ⌛️ Ready for Alignment |
| E2 | Upgrading your file | Getting your file ready for this version | This takes a moment. A copy of your file exactly as it is now is saved at ⟨path⟩ first, so nothing you've scanned is at risk. | None (it finishes on its own) | ⌛️ Ready for Alignment |
| E3 | Upgrade didn't finish | Your file is exactly as it was | Something stopped partway, so nothing was changed. Your file is still version ⟨version⟩ and this app expects ⟨version⟩, and the copy taken before the attempt is at ⟨path⟩. | Try again; Show me the copy | ⌛️ Ready for Alignment |
| E4 | A reading can't be read | One reading on ⟨code⟩ can't be read | The measurement itself is unreadable, so this swatch has no value until you scan it again. Everything else in ⟨collection⟩ is fine, and nothing has been removed. | Scan ⟨code⟩ again | ⌛️ Ready for Alignment |
| E5 | This file has a problem | Something's wrong with this file | It's open read-only so nothing makes it worse. The app can write out everything it can still read into a fresh file and leave this one untouched for you to keep. | Save what's readable; Leave it alone | ⌛️ Ready for Alignment |
| E6 | Export a collection | Export ⟨collection⟩ | ⟨n⟩ swatches, with everything you imported, the full wavelength readings, and every colour space — each one saying which illuminant, observer, and measurement condition it came from. Colours your screen can't show accurately are marked as such in the file too. | Export current readings; Export with full history ‹P1›; Choose where | ⌛️ Ready for Alignment |
| E7 | Export didn't finish | Nothing was written | ⟨collection⟩ is untouched and no half-finished file was left behind. There wasn't room, the folder isn't writable, or it's gone. | Choose somewhere else | ⌛️ Ready for Alignment |
| E8 | Delete a swatch ‹P1› | Delete ⟨code⟩? | This is the one thing that does throw data away. It takes the reading it has now, its ⟨n⟩ earlier readings, and everything recorded about scanning it. You can undo this until you quit SpectroCapture; after that it's final, so export first if you want to keep any of it. | Delete; Export first; Cancel | ⌛️ Ready for Alignment |
| E9 | The file changed outside the app | Your file changed somewhere else | Something outside SpectroCapture wrote to it, so what you're looking at may be out of date. Reading your file in another tool is always safe; changing it while the app is open isn't. | Read it again | ⌛️ Ready for Alignment |
| E10 | The file is open somewhere else | Another copy of SpectroCapture has this file | Two copies writing to one file would damage it. Close the other one, or open a different file here. | Open a different file | ⌛️ Ready for Alignment |
| E11 | Correction or re-measurement? | Has ⟨code⟩ changed, or was the old reading wrong? | Both keep the old reading — the difference is what it means later. If the swatch itself has changed, both readings were true and both belong in its history. If the first reading was a mistake, the old one is marked as never having been right and is left out of anything showing how ⟨code⟩ changed over time. | The swatch has changed; The old reading was wrong | ⌛️ Ready for Alignment |
| E12 | Save a copy of your file | Save a copy | This makes a complete, safe copy even while the app is running — ⟨size⟩, everything, including the history behind every swatch. Copying the file yourself in Finder while SpectroCapture is open can give you a damaged copy. | Save a copy | ⌛️ Ready for Alignment |
